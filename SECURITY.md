# Security Policy

## Supported Versions

Security fixes are generally applied to the current main development line.

## Reporting a Vulnerability

Please do not disclose security issues publicly before they are reviewed.

When reporting a vulnerability, include:

- a description of the issue
- affected versions or commits if known
- reproduction steps or a proof of concept
- impact assessment
- any suggested remediation if available

Use a private reporting channel where possible. If no dedicated private channel is configured, contact the maintainer directly and avoid opening a public GitHub issue.

## Response Expectations

The project will try to:

- acknowledge receipt of the report
- validate the issue
- prepare a fix or mitigation when appropriate
- publish a coordinated update when the issue is resolved
